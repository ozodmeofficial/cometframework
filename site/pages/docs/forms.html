A form with c-post (or c-put, c-patch) sends its fields as JSON on submit. With a file input it switches to multipart/form-data automatically.

ValidatsiyaВалидацияValidation

1) Brauzerning standart atributlari ishlaydi: required, type="email", minlength, pattern… 2) c-validate — o'z qoidangiz: true yoki xato matnini qaytaring. 3) Server 422 va { errors: { field: 'xabar' } } qaytarsa — xatolar avtomatik maydonlar yonida chiqadi.

1) Работают стандартные атрибуты: required, type="email", minlength, pattern… 2) c-validate — своё правило: верните true или текст ошибки. 3) Если сервер вернёт 422 и { errors: { field: 'сообщение' } } — ошибки сами появятся возле полей.

1) Native attributes just work: required, type="email", minlength, pattern… 2) c-validate is your own rule: return true or an error message. 3) If the server responds 422 with { errors: { field: 'message' } }, the errors appear next to the fields automatically.

Xato bo'lgan maydonlarga aria-invalid="true" va .c-invalid klassi qo'shiladi — CSS yoki Tailwind bilan bezang. Birinchi urinishdan keyin maydonlar yozilayotganda qayta tekshiriladi.

Невалидные поля получают aria-invalid="true" и класс .c-invalid — стилизуйте через CSS или Tailwind. После первой попытки поля проверяются заново при вводе.

Invalid fields get aria-invalid="true" and the .c-invalid class — style them with CSS or Tailwind. After the first attempt, fields re-validate as you type.

Optimistik yangilashОптимистичные обновленияOptimistic updates

c-optimistic ifodasi so'rovdan oldin darhol bajariladi. Server xato qaytarsa, holat avtomatik avvalgi qiymatga qaytariladi.

Выражение c-optimistic выполняется сразу, до запроса. Если сервер вернёт ошибку, состояние автоматически откатится.

The c-optimistic expression runs immediately, before the request. If the server fails, state is rolled back automatically.
